# Compatibility oracle notes

## Pinned Liana source

Use Liana tag `v9.0`, resolved annotated-tag commit `398e622596e7530a328de3027cb2c09905f708c6` (tag object `47c16fe1287573f49bee743bfcfd57bf9ab73387`). The Liana crate declares Miniscript 11.0; its `Cargo.lock` pins `miniscript` 11.2.0. Keep both the tag and lockfile version pinned when producing oracle vectors.

Relevant source locations:

- [`liana/src/descriptors/mod.rs`](https://github.com/wizardsardine/liana/blob/398e622596e7530a328de3027cb2c09905f708c6/liana/src/descriptors/mod.rs): Liana descriptor parsing and script/address derivation.
- [`liana/src/descriptors/analysis.rs`](https://github.com/wizardsardine/liana/blob/398e622596e7530a328de3027cb2c09905f708c6/liana/src/descriptors/analysis.rs): policy analysis and `unspendable_internal_xpub`; `bip341_nums` uses compressed point `0250929b74c1a04954b78b4b6035e97a5e078a5a0f28ec96d547bfee9ace803ac0`. The chain code hashes the ordered public-key encodings encountered by walking TapTree leaves and each Miniscript's `iter_pk()`.
- [`liana/src/descriptors/keys.rs`](https://github.com/wizardsardine/liana/blob/398e622596e7530a328de3027cb2c09905f708c6/liana/src/descriptors/keys.rs): key parsing and derived public-key representation.

The TypeScript package exposes `constructUnspendableInternalXpub` for the fixed NUMS point and ordered-key chain-code construction. The parser checks a ranged, origin-free NUMS internal xpub against originated extended public keys in textual TapTree order. Rust-generated descriptor vectors now cross-check this path across five policy cases; the synthetic test remains a separate unit test and is not the oracle.

## Rust-generated descriptor fixtures

`tests/fixtures/liana-v9-rust-taproot-multisig.json` contains five policies generated by `LianaPolicy::new` and serialized/derived by `LianaDescriptor::new` from the pinned Liana commit above: a single-key primary with one single-key recovery, a 3-of-3 primary with one 2-of-3 recovery leaf, a 3-of-3 primary using `<0;1>` with a 2-of-3 recovery using `<2;3>`, a 2-of-3 primary with three recovery paths (single-key, 2-of-3, and 1-of-3), and a 2-of-3 primary with three `multi_a` recovery paths (`older(42)` 2-of-3, `older(43)` 3-of-3, and `older(1678)` 1-of-3). The final descriptor is reparsed with `LianaDescriptor::from_str`, and Rust asserts the primary/recovery thresholds and timelocks. The fixture includes public descriptors and exact mainnet addresses plus `scriptPubKey` values for receive/change indices 0 and 1 (twenty address/script pairs). The oracle used Rust 1.80.0 and the Liana lockfile's Miniscript 11.2.0; no seed or private key is stored, and the harness consumes only public root xpubs. Regeneration instructions and the Rust harness are in `tests/oracle/README.md`.

The TypeScript test suite compares all twenty mainnet Taproot address/script pairs exactly. Pinned Rust fixtures from the single-primary Signet community descriptor compare receive/change indices 0–9 for `<0;1>`, nonstandard choices `<7;19>` and `<19;7>`, reuse the same originated xpub with ordered paths `<0;1>`/`<1;0>`, and rewrite the single-key recovery as `multi_a(1,key)` (twenty pairs each). The two nonstandard multipath fixtures confirm that receive/change selection preserves the descriptor tuple order rather than sorting branch indexes. The shared-xpub fixture confirms Liana's duplicate-key identity includes the ordered derivation paths: the same xpub is accepted with two distinct ordered path tuples and rejected for an identical xpub/path tuple by the negative vector. For the `multi_a(1,key)` candidate, Rust `LianaDescriptor::from_str` accepts the descriptor, asserts a primary `PathInfo::Single` and recovery `PathInfo::Single` at `older(36)`, then derives the outputs; this is a parser-derived positive vector, not a descriptor emitted by `LianaPolicy::new`. Pinned Rust Liana fixtures cover five P2WSH forms and twenty mainnet receive/change pairs at indices 0–1: single-key primary/recovery; 2-of-3 primary/recovery; 2-of-3 primary with three recovery paths (single-key, 2-of-3, 1-of-3); legacy `andor(pk(recovery),older(42),pk(primary))`; and a mainnet-instantiated version of the Liana v2 three-recovery threshold shape in `liana/src/descriptors/mod.rs::bip32_derivs_pruning` (primary 3-of-3, recovery `older(3)` 2-of-3 and `older(6)` 3-of-3). An additional fixture contains the exact public Signet descriptor from that v2 test and four Signet address/script pairs; it is parsed and derived by pinned Rust `LianaDescriptor::from_str`. Its tpubs use testnet extended-key serialization, while address encoding uses Signet parameters. Across these descriptor fixtures, 144 address/script pairs are compared against Rust. P2WSH parsing is bounded to the tested `or_d`, nested `or_i`, `andor`, and direct key-only `thresh` encodings; it enforces decimal positive timelocks and duplicate-key/origin checks, and rejects nested threshold policies. The `andor` and v2 threshold fixtures' primary/recovery mapping is asserted by the pinned Rust parser. The generic syntax AST retains exact source slices/offsets, ordered arguments/prefixes and binary Taproot tree topology for validated descriptors; it is not a complete Miniscript AST or proof of broader semantic compatibility.

`tests/descriptors-library-parity.test.ts` also evaluates `@bitcoinerlab/descriptors` against all 64 pinned Rust address/script pairs after positional expansion of multipath choices. This proves exact outputs for the checked vectors only; the production importer still applies its own bounded Liana policy validation and broader grammar/network behavior remains unverified.

## Signet fixture

`tests/fixtures/liana-v9-signet-single-primary-recovery.json` records the full receive/change descriptors, checksums and the first ten receive/change addresses from the community gist at <https://gist.github.com/jdlcdl/b17c6b551839adb5b7b7d4ef9574e48e>. The source reports Liana v9.0 and uses Bitcoin Core `deriveaddresses`; it is an independent cross-check for a single-key primary path with a 36-block recovery path. It is **not** a multisig or NUMS oracle, nor an upstream Rust-maintained test vector. Mnemonic/private material from the gist is deliberately excluded. The fixture also records the receive index-0 scriptPubKey.

`tests/fixtures/liana-v9-rust-signet-single-primary-recovery.json` is the pinned Rust cross-check for that same policy. Its input builder reconstructs the ordered `<0;1>` descriptor from the preserved receive/change branches and verifies they differ only in branch values; the Rust harness parses it through `LianaDescriptor::from_str`, asserts a single-key primary and single-key recovery at 36, then records exact Signet addresses and `scriptPubKey`s for receive/change indices 0–9 (20 pairs). No mnemonic, seed or private key is stored.

`tests/fixtures/liana-v9-rust-signet-single-key-multi-a.json` is a separate parser-derived positive vector: it mutates that public descriptor's recovery from `pk(key)` to `multi_a(1,key)`, then the pinned Rust parser accepts it and asserts the normalized primary/recovery mapping before deriving 20 exact Signet address/script pairs. It is explicitly not a `LianaPolicy::new`-generated descriptor; the harness and deterministic builders are in `tests/oracle/`.

`tests/fixtures/liana-v9-rust-signet-v2-bip32-derivs.json` is a separate pinned Rust oracle for the exact public Signet descriptor in the Liana v2 `bip32_derivs_pruning` test. It records four Rust-generated address/script pairs and preserves the source descriptor in `tests/oracle/liana-v2-signet-descriptor.txt`; it does not include the PSBT data from the upstream test.

## Semantic rejection cross-checks

`tests/fixtures/liana-v9-rust-policy-rejections.json` contains two valid Miniscript/Taproot descriptors which pinned Liana v9 rejects as incompatible policies: one has a hashlock inside a recovery path, the other constrains a primary tree leaf by a hashlock. The Rust harness asserts the exact Liana rejection message before emitting either fixture. The TypeScript importer rejects them too. This guards against classifying any leaf that merely contains `older()` or an originated key as a valid Liana path. It does not establish a complete Miniscript semantic parser: supported Taproot leaves remain key-only (`pk`/`multi_a`) primary leaves and key-only recovery policies paired with one block-based `older()`.

A pinned negative fixture, `liana-v9-rust-signet-fixed-branch-recovery.json`, records rejection as `LianaPolicyError::IncompatibleDesc` when the recovery signer uses a fixed `/0/*` branch while the spendable internal primary remains multipath. The TypeScript test verifies this exact mutation and rejects it. A separate source-derived test covers the distinct case where the internal primary itself is flattened while recovery remains multipath; it remains explicitly unrecorded as a Rust fixture. Fixed-branch community receive/change descriptors with no multipath anywhere remain accepted. The pinned Rust fixture `liana-v9-rust-signet-duplicate-xpub.json` records the related identity rule: reusing the spendable internal primary xpub and derivation path in the recovery while changing only the origin fingerprint is rejected as `LianaPolicyError::DuplicateKey`. The TypeScript test uses the valid-checksum Rust-parsed descriptor and rejects it too.

## Validation requirements

- Verify the stored descriptor checksums before using fixtures.
- Regenerate the Rust multisig fixture using the checked-in oracle harness and pinned commit/lockfile before changing expected outputs.
- Add vectors before claiming parity for policy or network shapes not covered by the checked-in fixture; keep gaps explicit.
